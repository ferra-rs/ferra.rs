forbidden

Forbidden

403 Forbidden

Returned when an authenticated caller fails a per-operation #[authorize] check — the request carried a valid bearer token, but the operation's authorization rule evaluated false (a missing role, or a rule the owner of the row does not fully satisfy). Since v0.9.0 a row that belongs to someone else is not a 403: under an IsOwner rule it answers 404 not_found, exactly like a row that does not exist, so the response never reveals that the row exists. New in v0.8.0 — the only addition to the closed ERROR_TYPES namespace since the cursor-pagination release (0.7.5).

403 vs 401. A 403 forbidden means the caller is authenticated but the operation is not permitted for them — retrying with credentials will not help (RFC 9110 §15.5.4). An absent or invalid credential is a 401 unauthorized instead (§15.5.2). A consumer's typed-union — and an AI agent — can branch on the two without guessing.

No-echo. The detail field is one of two constant literals, shown below. The framework never echoes the caller's identity claims, the row's #[field(owner)] value, or the failed rule's textual representation back to the client — every authorization-denial reason produces a byte-identical body, so the response cannot function as a probing oracle.

Cookie writes (v0.12.0). When the token arrives in a cookie, a request whose method is not GET, HEAD or OPTIONS is also a 403 forbidden unless it carries exactly one Origin header equal to an origin the application listed (a CSRF guard). A missing, null, repeated or unlisted Origin gets the second literal below, which never repeats the Origin it received, and the row is left unchanged.

Example RFC 7807 body

{
  "type":   "https://ferra.rs/errors/forbidden",
  "title":  "Forbidden",
  "status": 403,
  "detail": "you do not have permission to perform this operation on this resource"
}

Example RFC 7807 body, cookie write from an unlisted origin

{
  "type":   "https://ferra.rs/errors/forbidden",
  "title":  "Forbidden",
  "status": 403,
  "detail": "a write authenticated by a cookie must come from an allowed origin"
}
