Error type URIs

Every Ferra error response carries an RFC 7807 body whose type field is one of these fourteen URIs. The set is closed — no URI outside this table will ever appear on the wire.

Variant HTTP status Title Source
not_found 404 Not Found Resource Not Found FerraError::NotFound, FerraError::CollectionNotFound
validation 400 Bad Request Validation Error FerraError::Validation, FerraError::BadRequest
validation_failed 422 Unprocessable Content Validation Failed FerraError::Unprocessable
conflict 409 Conflict Conflict FerraError::Conflict
internal 500 Internal Server Error Internal Server Error FerraError::Internal
payload_too_large 413 Payload Too Large Payload Too Large request-body-limit middleware
rate_limited 429 Too Many Requests Too Many Requests rate-limit middleware
unauthorized 401 Unauthorized Unauthorized JWT layer, FerraError::Unauthorized, Foundry::with_docs_protected(…)
invalid_cursor 400 Bad Request Invalid Cursor FerraError::InvalidCursor
forbidden 403 Forbidden Forbidden FerraError::Forbidden
unsupported_media_type 415 Unsupported Media Type Unsupported Media Type FerraError::UnsupportedMediaType

not_found

Resource Not Found

404 Not Found

Returned by every read, update, or delete operation that resolves to zero matching rows — including a soft-deleted row, and a row that belongs to someone else under an IsOwner rule. A collection the caller may not use (a list or a create refused by a projection rule) answers the same 404 with the detail films not found, no ID. 

{
  "type":   "https://ferra.rs/errors/not_found",
  "title":  "Resource Not Found",
  "status": 404,
  "detail": "films/c2bb1f10-72b8-486a-9f2b-c92e4a2cdf41 not found"
}

validation

Validation Error

400 Bad Request

Returned when an inbound JSON body fails to parse or a path parameter cannot be deserialised. The errors array holds one entry whose field is "body" or "id"; a rejected collection query answers the same type with a detail and an errors entry naming the parameter. For #[field(…)] rule failures on a valid body, see validation_failed (422). 

{
  "type":   "https://ferra.rs/errors/validation",
  "title":  "Validation Error",
  "status": 400,
  "detail": "validation failed",
  "errors": [
    { "field": "body", "code": "invalid_json", "message": "expected `,` or `}` at line 1 column 14" }
  ]
}
Full documentation →

validation_failed

Validation Failed

422 Unprocessable Content

Returned when a well-formed JSON body deserialises into the model's request shape but one or more #[field(…)] rule constraints fail. Every violation is reported — the framework never short-circuits on the first error. Distinct from validation (400), which fires when the body cannot be parsed at all. 

{
  "type":   "https://ferra.rs/errors/validation_failed",
  "title":  "Validation Failed",
  "status": 422,
  "detail": "validation failed",
  "errors": [
    { "field": "title", "code": "min_length", "message": "must be at least 1 character" },
    { "field": "rating", "code": "max", "message": "must be at most 10" }
  ]
}
Full documentation →

conflict

Conflict

409 Conflict

Returned when a write would violate a unique constraint — a duplicate slug, primary-key collision, or similar. 

{
  "type":   "https://ferra.rs/errors/conflict",
  "title":  "Conflict",
  "status": 409,
  "detail": "the request conflicts with an existing resource"
}
Full documentation →

internal

Internal Server Error

500 Internal Server Error

Returned for any database or infrastructure failure not classifiable as one of the typed variants above. The detail field is always the constant literal "internal server error" — no internal path, crate name, or library substring is ever leaked. 

{
  "type":   "https://ferra.rs/errors/internal",
  "title":  "Internal Server Error",
  "status": 500,
  "detail": "internal server error"
}
Full documentation →

payload_too_large

Payload Too Large

413 Payload Too Large

Emitted when an inbound request body exceeds the configured cap (1 MiB by default; DoS protection). Emitted by the request-body-limit middleware, not through FerraError. 

{
  "type":   "https://ferra.rs/errors/payload_too_large",
  "title":  "Payload Too Large",
  "status": 413,
  "detail": "request body exceeds 1048576 bytes"
}
Full documentation →

rate_limited

Too Many Requests

429 Too Many Requests

Emitted by the framework's default rate-limiter on mutation routes (POST / PUT / DELETE). The response always carries a Retry-After header (whole seconds, at least 1), repeated in detail. 

{
  "type":   "https://ferra.rs/errors/rate_limited",
  "title":  "Too Many Requests",
  "status": 429,
  "detail": "rate limit exceeded; retry after 3 seconds"
}
Full documentation →

unauthorized

Unauthorized

401 Unauthorized

Returned when a route requires an identity and the request carries none that is valid: a missing, malformed, expired or refused bearer token. The response carries WWW-Authenticate: Bearer and a fixed detail. Also emitted by Foundry::with_docs_protected(verifier) for the docs surface. 

{
  "type":   "https://ferra.rs/errors/unauthorized",
  "title":  "Unauthorized",
  "status": 401,
  "detail": "valid credentials are required to access this resource"
}
Full documentation →

invalid_cursor

Invalid Cursor

400 Bad Request

Returned when a ?cursor=… query parameter cannot be decoded into a valid keyset-pagination token, or the token does not fit the collection's cursor key. The detail field is a fixed literal — the framework never echoes the bytes of the malformed cursor back to the client (no reflection oracle). Recovery: drop cursor and restart pagination. New in v0.7.5. 

{
  "type":   "https://ferra.rs/errors/invalid_cursor",
  "title":  "Invalid Cursor",
  "status": 400,
  "detail": "the supplied cursor token is invalid; drop the `cursor` query parameter and restart pagination"
}
Full documentation →

forbidden

Forbidden

403 Forbidden

Returned when an authenticated caller fails a per-operation #[authorize] check — distinct from a 401 unauthorized, which signals an absent or invalid credential. Since v0.12.0 it is also the answer to a write authenticated by a cookie that does not come from an allowed origin. The detail field is one of two fixed literals (the authorization one below, and "a write authenticated by a cookie must come from an allowed origin") — the framework never echoes the caller's claims, the row's owner value, the failed rule or the received Origin back to the client. New in v0.8.0. 

{
  "type":   "https://ferra.rs/errors/forbidden",
  "title":  "Forbidden",
  "status": 403,
  "detail": "you do not have permission to perform this operation on this resource"
}
Full documentation →

unsupported_media_type

Unsupported Media Type

415 Unsupported Media Type

Returned when a write request carries a body that is not declared as application/json. Checked after the authorization checkpoint; nothing is written. The detail field is a fixed literal. New in v0.9.0. 

{
  "type":   "https://ferra.rs/errors/unsupported_media_type",
  "title":  "Unsupported Media Type",
  "status": 415,
  "detail": "the request body must be JSON: send `Content-Type: application/json`"
}
Full documentation →

timeout

Request Timeout Budget Exceeded

503 Service Unavailable

The request exceeded its configured budget before a Ferra repository commit started. No change was committed; no Retry-After is sent. A started commit finishes without a cut. New in v0.11.0.

{"type":"https://ferra.rs/errors/timeout","title":"Request Timeout Budget Exceeded","status":503,"detail":"the request exceeded its time budget; no change was committed"}
Full documentation →

multiple_credentials

Multiple Credentials

400 Bad Request

The request carried more than one credential. Ferra refuses it before verifying any. New in v0.12.0.

{"type":"https://ferra.rs/errors/multiple_credentials","title":"Multiple Credentials","status":400,"detail":"send one credential per request"}
Full documentation →

identity_unavailable

Identity Unavailable

503 Service Unavailable

The credential could not be verified because the identity source is unavailable: the key set of the identity provider could not be fetched with no fresh key cached, or an API key lookup failed. One type and one detail for both causes; no Retry-After. New in v0.12.0.

{"type":"https://ferra.rs/errors/identity_unavailable","title":"Identity Unavailable","status":503,"detail":"the credential could not be verified; retry later"}
