Ferra.rs — User Guide

ferra-openapi

ferra-openapi is the framework’s documentation surface. It builds an OpenAPI 3.2 document from the description of each mounted model and serves it at /docs/openapi.json, plus an interactive Scalar page at /docs. Both are derived end-to-end from the same model that drives the routes, the SQL queries and the hypermedia links.

An application does not declare or call ferra-openapi: the crate has no public API of its own in 0.9. The way in is Foundry::with_docs() (or one of its variants below), and the way out is the running router: you read the document at /docs/openapi.json.

Dependencies. The examples on this page assume the dependencies of Getting started:

[dependencies]
ferra   = { git = "https://github.com/ferra-rs/ferra", tag = "v0.13.1" }
sea-orm = { version = "2.0", default-features = false, features = ["macros", "runtime-tokio-rustls", "sqlx-postgres"] }
tokio   = { version = "1", features = ["macros", "rt-multi-thread"] }
axum    = "0.8"
serde   = { version = "1", features = ["derive"] }

What you get for free

A Ferra model mounted through Foundry::with_docs() produces:

  • GET /docs/openapi.json — the full OpenAPI 3.2 document (openapi: "3.2.0").
  • GET /docs — interactive Scalar UI rendering the spec.
  • Every answer is documented. Each operation lists the error statuses the server can return for it — 400; 401 when the model reads tokens; 403 when the rule needs an identity; 404 on item routes; 409 on writes; 413 and 422 on bodies; 429 on mutations (not under no_rate_limit()); 500 — each an application/problem+json body. A chain with request_budget adds a 503 to every operation, and a chain whose JWT source is a key set (JwtConfig::key_set), or that accepts API keys (with_api_keys), adds it to the operations of the models that read tokens: all are the one named response ServiceUnavailable of components/responses ($ref to ProblemDetails; its type is timeout or identity_unavailable), never an inline response.
  • API keys are a security scheme. On a chain that accepts API keys, the document declares components/securitySchemes/apiKey (type: apiKey, in: header, name the configured header) and lists it as an alternative to bearer in the security of every operation that requires a credential.
  • The cookie is a security scheme. On a chain whose JwtConfig has with_cookie, the document declares components/securitySchemes/cookie (type: apiKey, in: cookie, name the configured cookie), lists it as an alternative next to bearer, and gives every mutation of a model that reads tokens the named response Forbidden (the 403 of a write whose Origin is not allowed), a $ref to ProblemDetails.
  • Collections match their pagination mode: page (page, per_page, total), cursor (next_cursor, required, a string or null) or both (either shape, as a oneOf that an answer matches one of only, by the keys each requires). These are the flat schemas, without _links.
  • Both representations are declared. Every negotiated 2xx lists application/json (the flat schema) and application/hal+json (the named schema <Model>Hal or <Model>CollectionHal, an allOf of the flat schema and {_links}). The items of a <Model>CollectionHal are <Model>Hal, since each item of a HAL list carries its own _links (0.13.0). In <Model>Hal, _links.self and _links.collection are optional: an item served to a caller who may list but not GET it has no self (0.13.0). A list’s own _links.self stays required.
  • A gated field is declared optional. A field with a #[field(read = …)] rule is never in the required list of its read schema and is described “absent when the caller may not read it”; its examples stay synthetic (a placeholder of its type, never a value of yours). The POST and PUT of a write projection that holds a field with a write rule declare 403, also on a model whose own rules are public (0.13.0).
  • An authority and a parent chain are declared. The POST and PUT of a model with #[ferra(authority)] declare the named 403 (the authority refuses a write with it), also on a model whose own rules are public; on such a model served with .with_auth() every operation declares 401 and the optional bearer requirement, since the layer reads tokens. The 422 of a model with owner(from) names the code reference_not_found in its description (0.13.0).
  • Blame columns are optional. The created_by and updated_by columns of a #[behavior(blameable)] model (under their configured names) are read-only optional strings in every read schema that lists them, described “absent when the caller may not read it”, and in no write schema (0.13.0).
  • A projection rule is declared. Every operation under a projection that carries an authorize rule declares 404 (a caller the rule refuses is told nothing, a list or a create included), and, when the rule needs an identity, 401 and the bearer security requirement (0.13.0).
  • Date filters. A DateTime, Date or Time filter field has filter[f] and filter[f][gt|gte|lt|lte] parameters with the field’s format (date-time, date; a Time has the HH:MM:SS[.fraction] pattern, as its schema does). A cursor-mode sort is an enum of the cursor key and its - form.
  • Projections: every projection route is documented, restore included, and the bare path shows the promoted projection when there is one.
  • Field names are the wire names. On a model that declares #[ferra(rename_all = "camelCase")], schemas, required lists, filter[...] parameters, sort values and examples all use the camelCase names.
  • Ferra’s own test suite checks this contract: every route of every test model is called with a request built from the document, and every answer is validated against it.

Foundry::with_docs() serves both routes to anyone who reaches the port. For any surface a network can reach, use Foundry::with_docs_protected(verifier), which answers an anonymous request with a 401: see Enabling the docs surface.

For each mounted model M (PascalCase struct name), the spec contains:

  • Five paths (GET /{resource}, GET /{resource}/{id}, POST /{resource}, PUT /{resource}/{id}, DELETE /{resource}/{id}).
  • Four projection schemas ({Model}, Create{Model}Input, Update{Model}Input, {Model}Collection).
  • A shared ProblemDetails schema referenced by every error response.
  • Every operation carries an operationId and a tags array containing the resource name. Zero inline schemas in operation definitions; every body schema is a $ref into components/schemas.

Collection operations (0.7.5 Enameling). The GET /{resource} operation’s parameter set is mode-aware: page-mode models emit page + per_page, cursor-mode emits per_page + cursor (with the ferra-cursor format identifier per spec 011 FR-029), and both- mode emits all three with the cursor parameter description quoting the mutual-exclusivity rule (FR-010 / FR-030). Adding a new #[field(filterable)] or #[field(sortable)] to the model automatically widens the OpenAPI filter[…] parameter list and the sort enum on the next emission (FR-032 / FR-033). See pagination.md for the consumer-facing surface.

/me

A model that declares #[ferra(me)] adds one more path, GET /me (under the version prefix: /v1/me), with the operationId getMe and no path parameter. Its responses are 200 (the model’s read schema), 401, 403 (a get rule that reads no row), 404 (every refusal that depends on the row answers it, see projections-and-routing.md § /me), and the 400 and 500 of every generated operation, all as ProblemDetails. The path has no other method.

Enabling the docs surface

For any surface a network can reach, the call site is Foundry::with_docs_protected(verifier): an anonymous request gets a 401 with an RFC 7807 body, and the verifier is yours to write.

use ferra::Foundry;
use axum::http::header::AUTHORIZATION;
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
mod film {
    use super::*;
    #[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
    #[sea_orm(table_name = "films")]
    #[ferra(auth = "none")]
    pub struct Model {
        #[sea_orm(primary_key)]
        pub id: i32,
        pub title: String,
    }
    #[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
    pub enum Relation {}
    impl ActiveModelBehavior for ActiveModel {}
}
use film::Model as Film;
fn demo(conn: sea_orm::DatabaseConnection) {
// Constant time: `==` on a secret stops at the first differing byte, and the delay tells it.
fn same(a: &[u8], b: &[u8]) -> bool {
    a.len() == b.len() && a.iter().zip(b).fold(0u8, |acc, (x, y)| acc | (x ^ y)) == 0
}
let docs_token = std::env::var("DOCS_TOKEN").unwrap_or_default();
let app = Foundry::new(conn)
    .mount::<Film>()
    .with_docs_protected(move |req: &axum::extract::Request| {
        let sent = req.headers().get(AUTHORIZATION).map_or(&[][..], |v| v.as_bytes());
        !docs_token.is_empty() && same(sent, format!("Bearer {docs_token}").as_bytes())
    })
    .build();
let _ = app;
}
fn main() {}

Foundry::with_docs() is for a local or internal service, where the inventory is the feature and nobody outside reaches the port:

use ferra::Foundry;
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
mod film {
    use super::*;
    #[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
    #[sea_orm(table_name = "films")]
    #[ferra(auth = "none")]
    pub struct Model {
        #[sea_orm(primary_key)]
        pub id: i32,
        pub title: String,
    }
    #[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
    pub enum Relation {}
    impl ActiveModelBehavior for ActiveModel {}
}
use film::Model as Film;
fn demo(conn: sea_orm::DatabaseConnection) {
let app = Foundry::new(conn)
    .mount::<Film>()
    .with_docs()
    .build();
let _ = app;
}
fn main() {}

That single chain produces a runnable HTTP service mounting Film’s five CRUD endpoints plus /docs/openapi.json and /docs with zero boilerplate.

Title, version and security

The document’s info.title and info.version are "API" and "1" unless you set them; the Scalar page uses the same title:

use ferra::{FerraIdentity, Foundry, JwtConfig};
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
mod article {
    use super::*;
    #[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
    #[sea_orm(table_name = "articles")]
    #[ferra(auth = "bearer")]
    pub struct Model {
        #[sea_orm(primary_key)]
        pub id: i32,
        pub title: String,
    }
    #[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
    pub enum Relation {}
    impl ActiveModelBehavior for ActiveModel {}
}
#[derive(Clone, Debug, Deserialize)]
struct MyClaims { sub: String }
impl FerraIdentity for MyClaims {
    fn id(&self) -> &str { &self.sub }
    fn has_role(&self, _role: &str) -> bool { false }
}
fn demo(conn: sea_orm::DatabaseConnection, jwt: JwtConfig) {
let app = Foundry::new(conn)
    .with_auth::<MyClaims>(jwt)
    .mount::<article::Model>()
    .with_docs()
    .with_docs_info("Films API", "2026.10")
    .build();
let _ = app;
}
fn main() {}

When a mounted model reads tokens, the document declares an HTTP bearer scheme named bearer (bearerFormat: JWT) in components.securitySchemes, and each operation says what it needs: security: [{"bearer": []}] when its rule needs an identity, [{}, {"bearer": []}] when a token is optional. The routes of with_docs() stay public; with_docs_protected gates them.

Every schema property carries examples (a one-element array: the Schema Object’s example keyword is deprecated since OpenAPI 3.1), every request body, parameter and header an example, and error responses are shared components.responses (BadRequest, Unauthorized, Forbidden, NotFound, Conflict, PayloadTooLarge, ValidationError, TooManyRequests, InternalServerError).

The document is built once, at Foundry::build(). If Ferra cannot finish it — a Ferra bug — build() panics with an explicit message rather than serve a document that silently lost part of its content.

Response headers of the docs page

The page loads one script, cdn.jsdelivr.net/npm/@scalar/api-reference@1.72.2/dist/browser/standalone.js, pinned to that file and checked by its Subresource Integrity hash, and fonts from fonts.scalar.com. A deployment that cannot reach those hosts gets no page; the document at /docs/openapi.json is served by your own process and is not affected.

Scalar’s telemetry and its agent tool are disabled in the served page, and Scalar’s request proxy (proxyUrl) is not set. The headers keep the page from reaching anything else, whatever a later Scalar default becomes:

  • GET /docs (the page; /api-docs with with_docs_at("/api-docs"); public or protected) sends
Content-Security-Policy: default-src 'none'; script-src https://cdn.jsdelivr.net/npm/@scalar/api-reference@1.72.2/dist/browser/standalone.js; style-src 'unsafe-inline'; font-src https://fonts.scalar.com data:; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
  • every response the docs routes produce (the HTML page, the JSON document, the protected variant’s 401) sends X-Content-Type-Options: nosniff. Only the HTML page sends the policy above: the 401 and the JSON document carry nosniff and no Content-Security-Policy. The 503 of the request budget is built outside the header layer of the docs routes and carries neither.

Ferra sets these two headers on the docs routes, inside the Foundry’s request-budget and cache layers, which leave them as set. Your own policy: a second Content-Security-Policy header added by an outer layer or a proxy is enforced together with Ferra’s, the stricter wins for each directive; a layer or proxy that overwrites the header replaces Ferra’s policy, and then the page is only as strict as yours.

Why the inventory is generated

The framework’s default-deny posture on model routes does not extend to with_docs(), which has no gate: it is meant for a local or internal service, where the inventory is the feature.

/docs/openapi.json is generated from the same ModelMeta IR that drives the routes. By construction, every endpoint a Ferra application exposes is documented, with no manual schema to keep in sync. This structurally closes OWASP API Security Top 10 API9:2023 (Improper Inventory Management) — the gap between the API a team thinks it exposes and the API actually deployed. Salt Security research cited in OWASP API9 measures that gap at 40% on average in production (one cited case: 54 undocumented endpoints, 12 exposing PII). The same document is also a map of the surface for whoever reads it, so who may read it is a choice: .with_docs_protected(verifier) gates the surface behind your verifier, and the inventory stays complete for the operators you let in.

Rule of thumb: prefer .with_docs_protected(verifier) for any surface a network can reach, and keep .with_docs() for local development and internal tools, where the inventory is the feature. The examples hello-ferra and movie-stars use .with_docs() for local development and listen on every interface (0.0.0.0:3000), so their page is public to anyone who can reach the port; examples/lambda-neon, the one that is deployed, mounts no documentation page and answers /docs like any unknown path.

The deviation from default-deny is recorded in ADR-0024 for the curious reader; this guide stands alone.

Naming conventions

Schema names

For a model named Film with no named projections declared, the spec carries four entries in components/schemas:

ProjectionOpenAPI schema namePurpose
ReadFilmResponse shape for GET and the body of POST / PUT responses.
CreateCreateFilmInputRequest body of POST /films.
UpdateUpdateFilmInputRequest body of PUT /films/{id}.
CollectionFilmCollectionResponse shape for GET /films ({ items: [Film], page, per_page, total }).

The schema name derives from resource_name (the URL path slug) via PascalCase singularisation.

Per-projection schemas

A model that declares one or more #[ferra(projection(...))] blocks emits four additional schemas per named projection (read, create, update and collection), plus the HAL forms of its read and collection schemas. For Film with one named admin projection (#[ferra(projection(name = "admin", read = […], write = […]))]):

ProjectionOpenAPI schema nameOperations served at
ReadFilmAdminGET /admin/films/{id}, GET /admin/films
CreateCreateFilmAdminInputPOST /admin/films
UpdateUpdateFilmAdminInputPUT /admin/films/{id}
CollectionFilmAdminCollectionGET /admin/films (pagination envelope)

The general rule:

  • Read schema: {Model}{Projection-PascalCase}.
  • Create schema: Create{Model}{Projection-PascalCase}Input.
  • Update schema: Update{Model}{Projection-PascalCase}Input.

For the default projection the {Projection-PascalCase} segment is the empty string, so the rule produces Film, CreateFilmInput, UpdateFilmInput.

{Model} is the singular of the resource name (films gives Film), never the Rust struct ident, which is Model in every Sea-ORM entity. The resource name is the one #[ferra(resource = "...")] gives, else the default of ferra-forge.md: the #[sea_orm(table_name)] literal, else a plural of the struct ident. The operationId of a projection’s route ends in the same {Projection-PascalCase} (getFilmAdmin, listFilmsAdmin), so it is not the default’s. Two models that name a projection alike keep a schema each.

A system_only model serves no write, so its document carries the Read and Collection schemas only (and their HAL forms), with no Create or Update schema, for the default projection and for each named one.

Each schema’s properties map carries exactly the field set the corresponding projection declares — no schema reuse via $ref from one projection to another. A reader scanning the document sees the per-projection shape without dereferencing chains.

Names are SDK-friendly: orval, openapi-generator, kiota, and their peers produce idiomatic, distinguishable types in the target language without post-processing. The framework’s internal Rust struct names (FilmReadProjection, FilmAdminReadProjection, …) NEVER leak into the published document — components/schemas keys, $ref values, operation IDs, and descriptions all carry only the public names from the tables above.

x-ferra-promoted-in vendor extension

When a named projection carries default = true with a breaking_change_version = "X.Y.Z" attestation (per ADR-0030 §Default-projection promotion safeguards), every operation served under the bare resource path gains an x-ferra-promoted-in: "X.Y.Z" vendor extension. SDK generators and downstream tooling (ferra anvil) surface the silent breaking change to consumers who might otherwise see only the URL stability.

operationId

Every operation carries a stable operationId:

MethodPathoperationId
GET/filmslistFilms
GET/films/{id}getFilm
POST/filmscreateFilm
PUT/films/{id}updateFilm
DELETE/films/{id}deleteFilm

The list id is list and the plural of the model name, made as the derive makes a resource name: Category gives listCategories, Box gives listBoxes, Film gives listFilms.

Versioned chains (Foundry::api_version("v1")) prefix the operationId with the version segment: v1.listFilms, v1.getFilm, etc.

tags

Every operation carries a single tag — the resource name in snake_case plural (films, actors). Scalar / Redoc / Swagger UI group operations by tag for easier navigation.

Field type mapping

Field types map to OpenAPI 3.2 schemas as follows:

Rust typeOpenAPI
String{ "type": "string" }
i32{ "type": "integer", "format": "int32" }
i64{ "type": "integer", "format": "int64" }
f32 / f64{ "type": "number" }
bool{ "type": "boolean" }
ferra::Id / Uuid{ "type": "string", "format": "uuid" }
Option<T>nullable T ({ "type": ["string", "null"] }) and absent from required
ferra::DateTime{ "type": "string", "format": "date-time" }
ferra::Date{ "type": "string", "format": "date" }
ferra::Time{ "type": "string", "pattern": "^([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9](\\.[0-9]{1,9})?$" }

Option<T> uses the nullable form of OpenAPI 3.1 and later (a type array containing "null"), not the 3.0 nullable: true keyword.

The three typed time newtypes (ferra::DateTime, ferra::Date, ferra::Time) are recognised by the framework and emit the right format. Direct use of legacy time crates (chrono::*, time::*, jiff::*) is rejected at the field-declaration site — see the §“Time vocabulary” section of ferra-core.md.

Field annotations

Four attributes shape what appears in each projection: #[ferra(skip)], #[ferra(read_only)], #[ferra(write_only)] and #[ferra(computed)].

#[ferra(skip)]

Excludes the field from every projection schema and from the wire contract. Useful for server-only state (audit timestamps, internal flags).

#![allow(unused)]
fn main() {
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
#[derive(Clone, Debug, PartialEq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
#[sea_orm(table_name = "films")]
#[ferra(auth = "none")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i32,
    pub title: String,
    #[ferra(skip)]
    pub internal_note: String,
}
#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {}
impl ActiveModelBehavior for ActiveModel {}
}

internal_note does not appear in Film, CreateFilmInput, or UpdateFilmInput, and the wire shape rejects an inbound value for that field.

#[ferra(read_only)]

The field appears in every read schema (Film and any per-projection read schema where the field is included) marked readOnly: true, and is structurally absent from every create / update input schema. Useful for server-assigned values that the consumer can read but cannot write.

#![allow(unused)]
fn main() {
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
#[derive(Clone, Debug, PartialEq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
#[sea_orm(table_name = "films")]
#[ferra(auth = "none")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i32,
    pub title: String,
    #[ferra(read_only)]
    pub indexed_at: ferra::DateTime,
}
#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {}
impl ActiveModelBehavior for ActiveModel {}
}

indexed_at appears in Film with readOnly: true; both CreateFilmInput and UpdateFilmInput omit the property entirely. If the model also declares a named admin projection that includes indexed_at in its read = [...] list, the field appears in FilmAdmin with readOnly: true and is omitted from CreateFilmAdminInput / UpdateFilmAdminInput.

#[ferra(write_only)]

The field appears in every write schema (CreateFilmInput / UpdateFilmInput / per-projection input schemas where the field is included), and is structurally absent from every read schema — not marked writeOnly: true on the read side, but simply missing. Useful for fields the consumer must supply on write but should never see on read (one-shot secrets, transient hints, write-side credentials).

#![allow(unused)]
fn main() {
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
#[derive(Clone, Debug, PartialEq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
#[sea_orm(table_name = "films")]
#[ferra(auth = "none")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i32,
    pub title: String,
    #[ferra(write_only)]
    pub new_password: String,
}
#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {}
impl ActiveModelBehavior for ActiveModel {}
}

new_password appears in CreateFilmInput and UpdateFilmInput; the Film read schema omits the property entirely. The framework guarantees the field cannot leak via a read operation — its absence is enforced at compile time on the generated read-projection struct.

#[ferra(computed)]

The field is server-derived (e.g., a derived count, a denormalised projection of joined rows). It appears in every read schema with readOnly: true, and is structurally absent from every write input schema — the framework calls FerraComputed::compute() / compute_async_batch() on read and never accepts the field as inbound input.

#![allow(unused)]
fn main() {
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
#[derive(Clone, Debug, PartialEq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
#[sea_orm(table_name = "films")]
#[ferra(auth = "none")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i32,
    pub title: String,
    #[sea_orm(ignore)]
    #[ferra(computed)]
    pub review_count: i64,
}
#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {}
impl ActiveModelBehavior for ActiveModel {}
impl ferra::compute::FerraComputed for Model {} // the default `compute` leaves the value as it is
}

review_count appears in Film with readOnly: true; the create and update inputs omit the property entirely. See ferra-core.md § Computed fields for the FerraComputed trait that drives the compute pipeline.

The shared ProblemDetails schema

Every error response in the spec references the same schema:

{
  "$ref": "#/components/schemas/ProblemDetails"
}

The schema’s body:

{
  "type": "object",
  "required": ["type", "title", "status"],
  "properties": {
    "type":   {
      "type": "string",
      "format": "uri",
      "enum": [
        "https://ferra.rs/errors/not_found",
        "https://ferra.rs/errors/validation",
        "https://ferra.rs/errors/conflict",
        "https://ferra.rs/errors/internal",
        "https://ferra.rs/errors/payload_too_large",
        "https://ferra.rs/errors/rate_limited",
        "https://ferra.rs/errors/unauthorized",
        "https://ferra.rs/errors/validation_failed",
        "https://ferra.rs/errors/invalid_cursor",
        "https://ferra.rs/errors/forbidden",
        "https://ferra.rs/errors/unsupported_media_type",
        "https://ferra.rs/errors/timeout"
      ]
    },
    "title":    { "type": "string" },
    "status":   { "type": "integer", "format": "int32" },
    "detail":   { "type": "string" },
    "instance": { "type": "string", "format": "uri-reference" }
  }
}

The closed enum on type is the load-bearing constraint: SDK generators produce a typed union over the URI set in the target language. An AI agent generating client code is foreclosed from fabricating new URIs — values outside the enum fail schema validation.

The full URI table (with HTTP status, title, and example body for every variant) lives in error handling.

Mounting an alternative UI

/docs/openapi.json is the framework’s stable spec endpoint; the Scalar UI at /docs is the bundled default but not the only choice. To use Redoc, RapiDoc or Swagger UI, serve it yourself and point it at /docs/openapi.json, which with_docs() mounts. ferra-openapi has no public API since 0.9.0: the document is reached through the running router, not through a function call.

Where the spec is built

Foundry::build() assembles the full document from the static ModelMeta of every mounted model. It runs once at process startup; the resulting document is cached and served unchanged on every /docs/openapi.json request — no per-request rebuild. Its title and version are set with with_docs_info(title, version).

Linting your spec

Ferra’s CI lints the generated reference document with vacuum 0.30.6 — Spectral cannot read OpenAPI 3.2 — using the workspace’s .spectral.yaml ruleset (Spectral-compatible), at the warn severity bar: any finding blocks the build. The ruleset extends the default OpenAPI rules with four Ferra rules (every operation declares tags and an operationId; request and response body schemas are $refs into components/schemas), and keeps oas3-missing-example and description-duplication on: the document carries an example for every property, body, parameter and header, and no description twice.

vacuum lint -r .spectral.yaml -n warn openapi.json

The same ruleset is a reasonable start for a downstream repository; add deployment rules to it (for example oas3-api-servers once the deployment declares servers).

These ADRs are not load-bearing for correct use of the feature; this guide stands alone.

JSON field schemas

A JSON field’s schema is {}: any JSON value. Supply a function returning a JSON Schema object or boolean with #[field(json(schema = crate::settings_schema))]. The served OpenAPI document inserts the function’s serde_json::Value verbatim; keywords such as const and $defs are retained. Optional JSON fields use anyOf: [<schema>, {"type": "null"}]. Schema overrides describe the API; write validation still follows the Rust type and declared JSON bounds.
