Ferra.rs — User Guide

ferra-core

ferra-core is the zero-I/O contract layer that every other Ferra crate depends on. An application does not declare it: it reaches what is public through the ferra facade (ferra::meta, ferra::model, ferra::error, ferra::Id, ferra::DateTime, ferra::Date, ferra::Time, ferra::date!). What the facade exports is the contract (stability.md, api/ferra-core.txt); the rest of the crate is #[doc(hidden)] and may change without notice.

ModuleItems an application reads
metaFieldType, FieldMeta, ModelMeta, and the rest of the description of a model
modelFerraModel
idId
errorIdParseError
timeDateTime, Date, Time, plus the date! macro

The crate performs no I/O and talks to no database. Its runtime dependencies are serde, uuid and jiff; utoipa (the OpenAPI schemas of the date types) and Sea-ORM’s value traits (so that Id and the date types are columns) sit behind the openapi and sea-orm Cargo features, which ferra-openapi and ferra-db enable for you: do not enable them yourself (Architecture).

Model metadata (FieldMeta / FieldType / ModelMeta)

The types of ferra::meta describe a resource precisely enough for downstream crates to derive HTTP routes, SQL, OpenAPI and hypermedia links from a single source of truth. #[derive(FerraModel)] writes them; an application reads them. FieldMeta and ModelMeta are #[non_exhaustive] and have no public constructor, so a description cannot be written by hand: a model is a Sea-ORM entity with the derive.

FieldType

A tag identifying the Rust type of a field. Option variants are spelled out so every field’s nullability is visible without indirection. FieldType is #[non_exhaustive]: a match on it needs a _ => arm to stay forward-compatible. This function names every variant of 0.9, and compiles:

#![allow(unused)]
fn main() {
use ferra::meta::FieldType;

fn label(ty: FieldType) -> &'static str {
    match ty {
        FieldType::String | FieldType::OptionString => "text",
        FieldType::I32 | FieldType::OptionI32 => "32-bit integer",
        FieldType::I64 | FieldType::OptionI64 => "64-bit integer",
        FieldType::F64 | FieldType::OptionF64 => "float",
        FieldType::Bool | FieldType::OptionBool => "boolean",
        FieldType::Uuid | FieldType::OptionUuid => "uuid",
        FieldType::Timestamp | FieldType::OptionTimestamp => "instant (DateTime)",
        FieldType::Date | FieldType::OptionDate => "calendar date",
        FieldType::Time | FieldType::OptionTime => "time of day",
        FieldType::ComputedUserNamed => "a type of the user's, on a `#[ferra(computed)]` field",
        _ => "a type added after 0.9",
    }
}
}

See the recognised field types table in ferra-forge.md for the end-user surface.

FieldMeta

The description of one field. Its public fields are individually named flags, so every one is grep-able and readable in IDE hover: name, wire_name (the JSON name, which differs from name under #[ferra(rename_all = ...)]), ty, required, readable, writable, skip_api, is_id, read_only, write_only, computed, filterable, sortable, cursor_key and validation_rules. There is no groups member since 0.14.0: groups had no effect and is a compile error (see FRG-137).

ModelMeta

The description of one resource: resource_name (the URL segment, "films"), table_name, primary_key_fields, fields, projections, operations, behaviors, pagination_mode, cursor_key_field_name, cursor_key_field_type, owner_field, auth_posture, authorize_rules and client_pk. It also answers field_by_wire_name, wire_name_of and renames_fields.

primary_key_fields carries the primary-key column names in declaration order. A single-key model holds a one-element slice and the route shape is /{resource}/{<pk>}; a composite-key model holds several and the route becomes /{resource}/{<pk1>}/{<pk2>}/….

Reading a description is what FerraModel::meta() is for:

#![allow(unused)]
fn main() {
use ferra::model::FerraModel;

fn describe<M: FerraModel>() {
    let meta = M::meta();
    println!("{} is served at /{}", meta.table_name, meta.resource_name);
    for field in meta.fields {
        let kind = if field.is_id {
            "key"
        } else if field.computed {
            "computed"
        } else {
            "column"
        };
        println!("  {} ({:?}): {kind}, wire name {}", field.name, field.ty, field.wire_name);
    }
}
}

The FerraModel trait

FerraModel binds a Rust struct to its static ModelMeta. #[derive(FerraModel)] implements it; do not implement it by hand (its description cannot be built outside the framework, and the derive is what declares the model’s authorization posture).

pub trait FerraModel: serde::Serialize + serde::de::DeserializeOwned + Send + Sync + 'static {
    fn meta() -> &'static ModelMeta;
}

Every bound is load-bearing:

BoundWhy it’s required
SerializeResponses are rendered from the model.
DeserializeOwnedRequest bodies are deserialised into it (no borrowed 'de).
Send + SyncModels participate in async handlers on a multi-threaded Tokio runtime.
'staticFerra models are owned values, never borrowed from request state.

A field whose type is not Send or Sync is reported in Ferra’s words, at the field (Compile-time diagnostics).

Id — the identifier primitive

Id is the identifier type every Ferra model uses. It is a 16-byte newtype wrapping uuid::Uuid.

Construction

#![allow(unused)]
fn main() {
use ferra::Id;

let a = Id::new();        // fresh UUID v7: time-ordered, collision-resistant
let b = Id::default();    // same as Id::new()
let n = Id::nil();        // all-zero sentinel — TEST FIXTURE ONLY
let _ = (a, b, n);
}

Id::nil() is explicitly a test fixture: it is distinguishable from any Id::new() output, which makes it useful as a sentinel in unit tests. Do not store or return Id::nil() from production code.

Wire format

Display emits the RFC 4122 hyphenated lowercase form (for example, "67e55044-10b1-426f-9247-bb680e5fe0c8"). FromStr accepts any of the four canonical UUID forms: hyphenated, simple (no hyphens), URN (urn:uuid:...), and braced ({...}). The serde impls delegate to Display / FromStr, so the wire representation is consistent across JSON, MessagePack, and every serde-backed format.

Full round-trip example

The same assertions run as a doctest of Id in crates/ferra-core/src/id.rs; this one is compiled with the guide.

#![allow(unused)]
fn main() {
use std::str::FromStr;
use ferra::Id;

// Construction.
let id = Id::new();

// Text round-trip.
let text = id.to_string();
let parsed = Id::from_str(&text)?;
assert_eq!(id, parsed);

// JSON round-trip.
let json = serde_json::to_string(&id)?;
let back: Id = serde_json::from_str(&json)?;
assert_eq!(id, back);

// Equality and the nil sentinel.
let nil = Id::nil();
assert_eq!(nil, Id::nil());
assert_ne!(nil, id);

// Parsing failure is typed, never a panic.
let err = Id::from_str("not a uuid").unwrap_err();
assert_eq!(err.to_string(), "failed to parse Id as a UUID");

// Id is Copy — passing by value is free.
fn takes_id(_x: Id) {}
takes_id(id);
takes_id(id);       // still valid, the previous call didn't move it.
Ok::<(), Box<dyn std::error::Error>>(())
}

Why a newtype

Wrapping uuid::Uuid rather than exposing it directly lets Ferra swap the inner representation later without churning every caller. The 16-byte payload is Copy; passing Id through the HTTP pipeline costs nothing at runtime.

Id is not PartialOrd / Ord. UUID v7 values sort by creation time at millisecond precision, but two ids created in the same millisecond have no defined order; order rows by a column you control. Id is also a column type: a ferra::Id field maps to a Postgres uuid column.

IdParseError

<Id as FromStr>::Err is IdParseError, a hand-written unit struct with a Display impl and a std::error::Error impl. Its inner is pub(crate), so you can only obtain an IdParseError by a parse failure — never by direct construction.

In later phases, IdParseError may grow variants distinguishing “wrong length” from “invalid character”. Because external code only ever matches it as an opaque error, adding variants will be a non-breaking change.

Time vocabulary (DateTime / Date / date!)

Ferra exposes one typed time vocabulary across the framework. Three #[repr(transparent)] newtypes — ferra::DateTime (an instant), ferra::Date (a calendar date) and ferra::Time (a time of day) — wrap the underlying time library so the framework can swap that library in a future release without a consumer-facing signature change. Reach the types through ferra::DateTime / ferra::Date / ferra::Time (or via ferra::prelude::*); never import the underlying time library directly.

DateTime — timestamp

DateTime represents a precise instant anchored to UTC. Wire format: RFC 3339 timestamp text ("2023-11-14T22:13:20Z").

ConstructorReturnsNotes
DateTime::from_second(seconds: i64)Result<DateTime, jiff::Error>seconds since the Unix epoch
DateTime::from_millisecond(milliseconds: i64)Result<DateTime, jiff::Error>milliseconds since the Unix epoch
DateTime::from_microsecond(microseconds: i64)Result<DateTime, jiff::Error>microseconds since the Unix epoch
DateTime::from_nanosecond(nanoseconds: i128)Result<DateTime, jiff::Error>nanoseconds since the Unix epoch
DateTime::from_duration(duration: jiff::SignedDuration)Result<DateTime, jiff::Error>epoch-relative duration
DateTime::now()DateTimereads the system clock; not const

The constructor names mirror the underlying time library verbatim; they are not invented. Names that do not exist on DateTime and will not be added: from_unix_timestamp, from_unix_nanos.

Each from_* constructor returns a Result and propagates an out-of-range argument as the underlying time library’s error type. The methods are not const fn — call sites use the standard ? operator, not const-context evaluation.

#![allow(unused)]
fn main() {
use ferra::DateTime;

fn epoch_seconds(seconds: i64) -> Result<DateTime, jiff::Error> {
    DateTime::from_second(seconds)
}

let now = DateTime::now();
let later = epoch_seconds(1_700_000_000)?;
let _ = (now, later);
Ok::<(), jiff::Error>(())
}

Date — calendar date

Date represents a time-zone-free calendar date. Wire format: RFC 3339 calendar date text ("YYYY-MM-DD").

ConstructorReturnsNotes
Date::new(year: i16, month: i8, day: i8)Dateconst fn; out-of-range triple is a const-eval error

Date::new is const fn — an out-of-range (year, month, day) triple is rejected at cargo build time, not at runtime:

#![allow(unused)]
fn main() {
use ferra::Date;

const RELEASED: Date = Date::new(2027, 1, 1);
// const INVALID: Date = Date::new(2027, 13, 1); // would not compile
}

date! macro — hyphen-literal calendar dates

ferra::date!(YYYY-MM-DD) re-tokenises a hyphen-literal into Date::new(year, month, day). Same compile-time validation as Date::new:

#![allow(unused)]
fn main() {
use ferra::{Date, date};

const SUNSET: Date = date!(2027-01-01);
// const INVALID: Date = date!(2027-13-01); // const-eval error
}

The macro is the recommended call site for fixed dates (release sunsets, scheduled migrations) because the literal form is most readable. Use Date::new(...) directly when the inputs are computed or come from configuration.

Time — time of day

Time is a time of day without date or time zone. Wire format: "HH:MM:SS", with an optional fraction ("09:30:00", "23:59:59.5").

ConstructorReturnsNotes
Time::new(hour: i8, minute: i8, second: i8)Timeconst fn; an out-of-range triple is a const-eval error
"09:30:00".parse::<Time>()Result<Time, jiff::Error>FromStr

DateTime and Date implement FromStr too (RFC 3339 text).

Use as model fields

The three types are column types. Each maps to one Postgres type and round-trips through the database and through JSON:

Field typePostgres columnJSON
ferra::DateTimetimestamptz"2026-10-01T09:30:00Z" (RFC 3339, UTC)
ferra::Datedate"2026-10-01"
ferra::Timetime"09:30:00"

Option<T> of each is a nullable column. Postgres stores microseconds: a DateTime or a Time is rounded down to the microsecond when written, so what you read back is the written value truncated to microseconds.

#![allow(unused)]
fn main() {
use ferra::{Date, DateTime, FerraModel, Time};
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
#[derive(Clone, Debug, PartialEq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
#[sea_orm(table_name = "events")]
#[ferra(auth = "none")]
pub struct Model {
    #[sea_orm(primary_key)]
    pub id: i32,
    pub at: DateTime,          // timestamptz NOT NULL
    pub day: Date,             // date NOT NULL
    pub opens: Time,           // time NOT NULL
    pub ends_at: Option<DateTime>, // timestamptz NULL
}
#[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
pub enum Relation {}
impl ActiveModelBehavior for ActiveModel {}
}

Import the three from ferra, not from Sea-ORM’s prelude, which has types of the same names: an explicit use ferra::{Date, DateTime, Time}; takes precedence over the glob (and use ferra::prelude::* does the same for an application that declares no sea-orm). There is no timetz, no zone-less date-time and no duration type yet.

These types are columns because ferra-core implements Sea-ORM’s value traits for them, behind its sea-orm Cargo feature. Do not enable that feature yourself: ferra-db enables it, so it is on in every application that uses the ferra facade. It is tied to Sea-ORM 2.x and adds no I/O dependency to ferra-core.

Use as deprecation dates

FoundryBuilder::deprecated(since, sunset) takes two Dates and returns Result<_, DeprecationError>: a sunset earlier than since is refused. Every response under the deprecated version carries Deprecation: @<seconds> (RFC 9745: the start of since, UTC) and Sunset: <HTTP-date> (RFC 8594: the last second of sunset, for example Tue, 05 Jan 2027 23:59:59 GMT):

use ferra::{Foundry, date};
use ferra::FerraModel;
use sea_orm::entity::prelude::*;
use serde::{Deserialize, Serialize};
mod film {
    use super::*;
    #[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel, FerraModel, Serialize, Deserialize)]
    #[sea_orm(table_name = "films")]
    #[ferra(auth = "none")]
    pub struct Model {
        #[sea_orm(primary_key)]
        pub id: i32,
        pub title: String,
    }
    #[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
    pub enum Relation {}
    impl ActiveModelBehavior for ActiveModel {}
}
use film::Model as Film;
fn demo(conn: sea_orm::DatabaseConnection) -> Result<(), Box<dyn std::error::Error>> {
let app = Foundry::new(conn)
    .api_version("v1")?
    .mount::<Film>()
    .deprecated(date!(2026-07-01), date!(2027-01-05))?
    .build();
let _ = app;
Ok(())
}
fn main() {}

Banned imports

A field typed with another time library does not compile: #[derive(FerraModel)] rejects a field whose type path starts with chrono::, time:: or jiff::, and names the Ferra type to use instead:

error: field type uses the `chrono` time crate; a Ferra model types time values with `ferra::DateTime` (an instant), `ferra::Date` (a calendar date) or `ferra::Time` (a time of day)
         help: replace it with `ferra::DateTime`, `ferra::Date` or `ferra::Time` (Postgres `timestamptz`, `date`, `time`); the wire format is RFC 3339
         note: docs/user-guide/ferra-core.md § Time vocabulary

cargo deny check also bans the chrono and time crates from the dependency graph, except where the Sea-ORM ecosystem and Ferra’s own column adapter use them.

Why newtypes

The three newtypes are #[repr(transparent)] over the underlying library’s value types. The layout is identical to the inner type, so a future release that replaces the underlying library does so at the ferra-core::time module boundary alone — consumer-facing signatures stay stable. The inner field is pub(crate); consumers reach the value only through ferra::DateTime / ferra::Date.

The OpenAPI schema emission is encapsulated in the same module: DateTime and Date emit {type: "string", format: "date-time"} and {type: "string", format: "date"}; Time emits {type: "string", pattern: "^([01][0-9]|2[0-3]):[0-5][0-9]:[0-5][0-9](\.[0-9]{1,9})?$"} (JSON Schema’s time format requires a time-zone offset, which a time of day does not have). Consumers and downstream crates never write the schema literal — the typed-newtype contract preserves the framework’s “single source of truth” rule.

Public surface

RequestContext

RequestContext (canonical path: ferra::request_context::RequestContext) is the request-scoped handle the framework hands to application code: the ctx parameter of FerraComputed::compute_async and FerraComputed::compute_async_batch (empty there in 0.13), and the context of the authorities and hooks that read it. It answers who the caller is and what the request carried:

AccessorAnswers
subject() -> Option<&str>the caller’s FerraIdentity::id(), None when anonymous
is_authenticated() -> boola verified identity is present
has_role(&str) -> boolthe identity’s FerraIdentity::has_role
claims::<C>() -> Option<&C>the typed claims of a bearer or cookie token; None for an API key, an anonymous request, or when C is not the type given to .with_auth::<C>()
api_key() -> Option<&ApiKeyIdentity>the identity of the API key that authenticated the request
header(&str) -> Option<&str>the first value of a request header, case-insensitive; None when absent or not UTF-8

A model with neither an authority nor owner(from) gets RequestContext::empty(): every accessor answers None or false.

A hook receives the context of the model it is declared on, and tx.resource::<N>() hands that same context to the authority of N (not a context built for N).

  • Credentials never reach it. Authorization, Proxy-Authorization, Cookie and the Foundry’s API key header are dropped when the context is built, in any case, so header() answers None for them, and Clone and Debug cannot carry them. Debug prints the subject and the header names, never a value.
  • Every other header is client-supplied. header("X-Forwarded-For") returns what the client sent, as is: do not authorize on X-Forwarded-*, Forwarded, Host or Origin unless your own trusted proxy sets them.
  • Not Copy. Since 0.13.0 the type owns an Arc and a header list: it is Clone, no longer Copy, UnwindSafe or RefUnwindSafe (migration note).

For the consumer-facing usage of the surrounding pipeline, see ferra-forge.md § Computed fields.

JSON documents

serde_json::Value, bare Value, Sea-ORM’s prelude alias Json, and their Option forms are JSON fields. A typed Serialize + Deserialize struct stored with Sea-ORM’s FromJsonQueryResult opts in with #[field(json)]. sea_orm::Value is a SQL value enum and is not a JSON document type.

Before typed deserialization, a JSON field allows at most 32 container levels and 65,536 compact serialized bytes. Overrides use #[field(json(max_depth = 8, max_bytes = 4096))]; max_depth accepts 1–126, max_bytes a positive integer. Exceeding a limit returns 422 json_too_deep or json_too_large before any write. The JSON parser’s own 128-level limit returns 400 invalid_json first. An optional field accepts null. JSON fields cannot be filtered, sorted, or cursor keys (FRG-355).

An application declaring Sea-ORM with default-features = false must enable "with-json" beside "macros", "runtime-tokio-rustls", and "sqlx-postgres". ferra::meta::FieldMeta::json exposes the compiled JsonBounds description.
