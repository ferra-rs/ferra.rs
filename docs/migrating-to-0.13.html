Ferra.rs — User Guide

Migrating from 0.12 to 0.13

0.13.0 (Engraving) changes what a projection, a field and a response may say. Each entry below is a change that can stop a 0.12 application from compiling or alter an answer; read the entries, then update the application’s git dependency to v0.13.0. CHANGELOG.md lists every change.

A projection names the deletion column in read (FRG-357)

Before. read = [id, title, deleted_at] on a #[behavior(soft_delete)] model compiled, and the response silently carried neither the column nor an error.

After. It does not compile: FRG-357.

Migration. Remove the deletion column from read = [...]. The response is the same as before, since the column was never served.

A projection names a #[ferra(skip)] field in read (FRG-358)

Before. read = [id, title, audit_blob] with audit_blob declared #[ferra(skip)] compiled, and the projection’s routes served the field.

After. It does not compile: FRG-358.

Migration. Remove the field from read = [...] (the routes then stop serving it), or remove #[ferra(skip)] from the field if the API should serve it.

_links.restore is gone from served rows

Before. Every live row of a soft-delete model carried _links.restore.href, a link that answered 404 on that live row.

After. A served row has no restore link. restore is still a route and is still in the OpenAPI document.

Migration. Build {prefix}/{resource}/{id}/restore yourself, or read it from OpenAPI, and call it on a row you know was deleted. Do not derive it from _links.self, which can be absent (next entry).

_links.self and _links.collection can be absent

Before. Every item carried _links.self and _links.collection, and the HAL item schema required self.

After. _links.self is present only if the caller may GET the row, and _links.collection only if the caller may list the collection. A caller who may list but not read a row gets the row without self. The HAL item schema no longer requires self.

Migration. A client or a generated SDK that assumed self must handle its absence. Under a projection prefix the links now carry the prefix (a fix: they pointed at the bare path before).

A create the caller may not read answers 201 with no body

Before. A caller who may create but not GET the new row received the row (its id, its stamps) and a Location header, or 204 and Location under Prefer: return=minimal.

After. Such a caller receives 201 Created with no body and no Location, also under Prefer: return=minimal. An admitted caller keeps the representation, or 204 under return=minimal, and its Location is the self link of the row. This closes a leak (SEC-008 bis): the id and the server-set values of a row the caller may not read.

Migration. A client that creates and then reads the Location must be allowed to GET the row, or look the row up by other means. Allow get for the roles that create, if they should read what they create.

An update or a restore the caller may not read answers 204 with no body

Before. A caller who may PUT or restore a row but not GET it received the row (its id, its stamps, its author) in the 200.

After. Such a caller receives 204 No Content with no body, whatever Prefer asked, and the write is done. An admitted caller keeps the 200 with the row, or 204 under return=minimal. Preference-Applied: return=minimal is echoed only when return=minimal was asked. This closes the same leak as the create (SEC-008 bis).

Migration. A client that reads the answer of a PUT or a restore must be allowed to GET the row, or read it separately. Allow get for the roles that write, if they should read what they write. A hand-written route on Resource::update serves what it chooses.

A hand-written model must carry the hook slot

Before. A hand-written FerraModel (no derive) that satisfied Mountable could be mounted.

After. Mountable also requires the hidden hook slot FerraDraft, with a runner for its Hooks. The derive writes it for every model, so a derived model changes nothing. (0.14.0 adds the Actions slot to it: see migrating to 0.14.)

Migration. Add to a hand-written, mounted model:

#![allow(unused)]
fn main() {
use ferra::ferra_core::hooks::{FerraDraft, NoActions, NoHooks};

struct Film;

impl FerraDraft for Film {
    type Draft = ();
    type Hooks = NoHooks;
    type Actions = NoActions;
}
}

Draft = () also satisfies the bound Mountable puts on the draft (ApplyDraft for the entity’s active model, DeserializeOwned and Send). A model that is only derived needs nothing. Hand-writing a model is outside the contract, which is the derive (see stability.md).

A hand-written model must carry the authority traits

Before. A hand-written FerraModel (no derive) that satisfied Mountable could be mounted.

After. Mountable also requires FerraAuthority and the hidden FerraAuthorityScope. The derive writes both for every model (an authority that allows everything without #[ferra(authority)]), so a derived model changes nothing.

Migration. Add to a hand-written, mounted model:

#![allow(unused)]
fn main() {
use ferra::authority::{AuthorityError, FerraAuthority};
use ferra::condition::Condition;
use ferra::ferra_core::authority::FerraAuthorityScope;
use ferra::meta::Operation;
use ferra::request_context::RequestContext;

struct Film;

impl FerraAuthority for Film {
    fn can(_: &RequestContext, _: Operation, _: &Self) -> Result<bool, AuthorityError> {
        Ok(true)
    }
}

impl FerraAuthorityScope for Film {
    fn scope_filter(_: &RequestContext) -> Option<Result<Condition<Self>, AuthorityError>> {
        None
    }
}
}

Ok(true) and None are what the derive writes without #[ferra(authority)]: no authority, no condition. Hand-writing a model is outside the contract, which is the derive (see stability.md).

A hand-written model must carry the owner chain and the derived views

Before. A hand-written FerraModel could be mounted without FerraOwnerChain, and could implement FerraViews by hand.

After. Mountable also requires the hidden FerraOwnerChain, and FerraViews has a required hidden method read_object. The derive writes both, so a derived model changes nothing.

Migration. Add to a hand-written, mounted model without owner(from = ..):

#![allow(unused)]
fn main() {
use ferra::ferra_core::meta::FerraOwnerChain;

struct Film;

impl FerraOwnerChain for Film {
    type Parent = Self;
    const FOREIGN_KEY: Option<&'static str> = None;
}
}

FerraViews cannot be written by hand any more: derive FerraModel. Hand-writing a model is outside the contract, which is the derive (see stability.md).

New: #[ferra(hooks)] (application code inside a write)

Nothing changes for a model that does not declare it. To run your own code inside the write’s transaction, add #[ferra(hooks)] to the model and write impl ferra::hooks::FerraHooks for Model (every hook has a default that does nothing). The key without the impl, and the impl without the key, are FRG-129; a key inside hooks(...) is FRG-132. before_save rewrites ModelDraft, which the derive writes for the model. See behaviors.md.

New: GET /me

Nothing changes for a model that does not declare it. To serve the caller’s own row at GET /me, add #[ferra(me)] to the model that has a unique root #[field(owner)] (#[sea_orm(unique)] on it, or the single-column primary key: FRG-131 otherwise) and mount it with .with_auth() (FRG-151 otherwise). One model per Foundry, and no model whose resource (its URL segment: the table_name, or #[ferra(resource = "...")]) is me: build() panics with a message that names the models. A .route("/me", ...) of your own now conflicts with it, and build() panics on that too. See projections-and-routing.md.

New: #[behavior(blameable)] (blame columns)

Nothing changes for a model that does not enrol it. To record who wrote a row, add #[behavior(blameable)] and two TEXT NOT NULL columns to the table (created_by, updated_by; the names are configurable). The migration, who may read the columns (read = <rule>, Authenticated by default) and the compile error for an operation an anonymous caller may call (FRG-121) are in behaviors.md. Give your identity type’s FerraIdentity::id() (conventionally the JWT sub, see ferra-auth.md) a verified, stable, non-empty value: a write with no subject is a 500 and nothing is written.

A projection widens exposure without authorize (FRG-117)

Before. A projection could list in read or write a field the bare path does not expose or accept, with nothing saying who may use it: its routes followed the model’s rules, as the bare path does.

After. It does not compile: FRG-117. A projection that shows or accepts less than the bare path, or the same, is unaffected, with one exception. If you promoted a projection to the bare path (default = true) and gave it an authorize rule, that rule protects the bare path only; every other projection of the model must then declare its own authorize (a rule, or inherit), whatever fields it shows.

Migration. Add authorize = <rule> to the projection (for example authorize = HasRole("editor") | IsAdmin; the rule grammar is in ferra-auth.md § Authorization rules): the rule is added to the model’s rule of each operation, and a caller it refuses gets a 404. If the model’s rules are enough, write authorize = inherit to keep the 0.12 behavior knowingly.

RequestContext is filled and is no longer Copy

Before. RequestContext was an empty Copy marker: let c = ctx; left ctx usable, and the type was UnwindSafe and RefUnwindSafe.

After. It carries the caller (subject(), is_authenticated(), has_role(), claims::<C>(), api_key()) and the request headers (header()). It owns an Arc and a header list, so it is Clone but no longer Copy, UnwindSafe or RefUnwindSafe. Authorization, Proxy-Authorization, Cookie and the Foundry’s API key header are dropped when it is built, so header() answers None for them and Debug prints the subject and the header names, never a value. Every other header is client-supplied (X-Forwarded-*, Host, Origin as sent). See ferra-core.md.

Migration. Code that copied a RequestContext (let c = *ctx;, a Copy bound, a const fixture used twice) calls .clone() instead. The FerraComputed signatures take &RequestContext and do not change in 0.13 (0.15 replaced the three methods: see migrating-to-0.15.md). Code that moved one across catch_unwind needs AssertUnwindSafe.
